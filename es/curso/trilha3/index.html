MÓDULO 3.1

AGENTS, Skills y memoria

Crear instrucciones de proyecto y una capacidad reutilizable con criterio de revisión.

0% 0 de 0

Qué es

AGENTS.md es el archivo de instrucciones que Codex descubre en el ámbito aplicable. Describe cómo trabajar: archivos iniciales, comandos de verificación, límites y formato de entrega. No es necesario explicar toda la historia de la organización; prefiera reglas cortas que alteren una decisión real.

Por qué aprender

Las instrucciones objetivas evitan repetir los mismos detalles en cada conversación. El archivo debe ayudar al agente a elegir una acción concreta, como verificar el informe antes de considerarlo finalizado.

Conceptos clave

Instrucción operativa; alcance; regla observable; concisión.

Qué es

Por defecto, ~/.codex/AGENTS.md guarda instrucciones globales. En el proyecto, AGENTS.md añade reglas específicas; los archivos en carpetas más cercanas pueden prevalecer en el ámbito correspondiente. AGENTS.override.md tiene prioridad sobre AGENTS.md en el mismo nivel. Esto no supera instrucciones del sistema, permisos o la solicitud explícita de la sesión.

Por qué aprender

La ruta importa. Una regla local puede no aplicarse a otra carpeta, y un archivo override olvidado puede explicar un comportamiento inesperado. Mantenga lo global pequeño y deje los detalles locales en el proyecto.

Conceptos clave

Descubrimiento; jerarquía; alcance de directorio; override.

Qué es

Una Skill reúne instrucciones de una actividad recurrente, con nombre y descripción al inicio de SKILL.md. Puede incluir recursos y programas de apoyo. Las Skills personales quedan en ~/.agents/skills; las del proyecto pueden quedar en .agents/skills dentro del repositorio. La carpeta ~/.codex sigue siendo la configuración de Codex.

Por qué aprender

Una regla indica qué respetar; una Skill enseña un procedimiento que puede activarse cuando sea necesario. Separar estos papeles evita cargar todo el manual en todas las tareas.

Conceptos clave

Nombre; descripción de activación; procedimiento; entrada y salida; validación.

Qué es

La memoria operativa del curso es un conjunto de archivos consultables, no un cambio en los pesos del modelo. Funciona cuando el agente lee la información relevante y cuando alguien mantiene esa información actualizada. Guarde hechos estables, decisiones y causas de fallas; no preserve cada frase de cada conversación.

Por qué aprender

Copiar todo el historial aumenta el volumen y puede reintroducir instrucciones antiguas. Una memoria pequeña, datada y revisada ayuda más que un archivo inmenso que nadie puede validar.

Conceptos clave

Memoria externa; consulta explícita; resumen; validez; fuente.

Qué es

Registre el síntoma, la causa observada, la corrección mínima y cómo verificar. Diferencie falla de solicitud, como objetivo ambiguo, de falla de infraestructura, como proceso terminado. El registro solo genera aprendizaje operativo cuando altera el procedimiento siguiente.

Por qué aprender

Rehacer todo el proyecto puede enmascarar un problema simple. Una pequeña protección, como verificar la existencia de un archivo antes de leerlo, suele ser más fácil de probar y mantener.

Conceptos clave

Síntoma no es causa; corrección mínima; prevención; evidencia.

Qué es

Prueba la Skill con una entrada normal, otra incompleta y una fuera de alcance. Observa si el resultado preserva datos, señala incertidumbre y se detiene cuando debería. La prueba debe medir comportamiento, no solo buscar el nombre de la Skill en la respuesta.

Por qué aprender

Un procedimiento que funciona una vez puede estar dependiendo de un contexto accidental. Variar entradas ayuda a descubrir lo que necesita quedar explícito en las instrucciones.

Conceptos clave

Caso normal; caso incompleto; límite de alcance; criterio de aceptación.

MÓDULO 3.2

Git y GitHub sin perder trabajo

Guardar una versión, inspeccionar diferencias y recuperar un cambio de entrenamiento.

0% 0 de 0

Qué es

Git registra versiones de archivos. Repositorio es la carpeta acompañada por este historial; commit es un registro con cambios y mensaje. GitHub es un servicio que aloja repositorios remotos. Puedes usar Git localmente sin publicar nada en internet.

Por qué aprender

Cuando un agente altera muchos archivos, el historial permite entender qué cambió y recuperar una versión conocida. Git no sustituye la copia de seguridad de todo: archivos ignorados, bases de datos y datos externos necesitan protección propia.

Conceptos clave

Repositorio; commit; historial; remoto; backup.

Qué es

git status muestra archivos nuevos, modificados y preparados. git diff muestra cambios aún no preparados; git diff --cached muestra lo que irá al próximo commit. El área de preparación, llamada staging, permite elegir exactamente qué archivos pertenecen al mismo cambio.

Por qué aprender

git add . prepara todo lo que no está ignorado. Para aprender, prefiere nombrar archivos: percibes mejor el alcance y reduces el riesgo de incluir material sin relación.

Conceptos clave

Árbol de trabajo; staging; diff; revisión de contenido.

Qué es

Configura user.name y user.email localmente para identificar la autoría. Prepara los archivos deseados y usa git commit -m con una descripción concreta. Un commit debe representar un cambio que puedas explicar y verificar.

Por qué aprender

Mensajes como “update” hacen que el historial sea poco útil. Una versión solo es un punto confiable si sabes si funcionaba y qué verificaciones se hicieron.

Conceptos clave

Autoría; mensaje; cambio cohesivo; verificación.

Qué es

git clone copia un repositorio remoto y su historial. git pull busca e integra cambios en la rama actual. Antes de actualizar, revisa git status. En un flujo inicial, git pull --ff-only acepta solo una actualización directa y se detiene cuando los historiales divergieron.

Por qué aprender

Actualizar una carpeta con cambios locales puede generar conflictos. El bloqueo del --ff-only es información útil: no lo eludas borrando trabajo. Inspecciona el historial o pide ayuda con el contexto.

Conceptos clave

Clone crea la carpeta; pull actualiza; branch es una línea de trabajo; divergencia pide revisión.

Qué es

git revert crea un nuevo commit que deshace un cambio anterior. Es adecuado para corregir un registro ya compartido. git restore descarta cambios no guardados de archivos elegidos; puede perder trabajo. No enseñes reset --hard como respuesta automática para cualquier dificultad.

Por qué aprender

Las herramientas de recuperación tienen consecuencias diferentes. Identifique si el cambio está solo en el archivo, en un commit local o publicado antes de elegir el comando.

Conceptos clave

Revert preserva el historial; restore descarta los cambios seleccionados; la recuperación exige diagnóstico.

Qué es

git push envía commits al remoto. Antes de eso, verifique la cuenta, la URL de destino, el alcance de los archivos y la ausencia de credenciales. Un repositorio público queda accesible a terceros; el privado también requiere control de acceso. Publicar un sitio es una etapa adicional, según el alojamiento.

Por qué aprender

Mezclar guardar y publicar lleva a una exposición accidental. Separe “registrar localmente”, “enviar a GitHub” y “poner el sitio en línea” en su lista de verificación.

Conceptos clave

origin; push; visibilidad; credenciales; publicación.
