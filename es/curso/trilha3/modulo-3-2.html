Git y GitHub sin perder trabajo

Guardar una versión, inspeccionar diferencias y recuperar un cambio de entrenamiento.

0% 0 de 0
6 temas
~45 min lectura y práctica
1 entrega verificable
Guiado laboratorio de entrenamiento

1Git es el historial del proyecto

Qué es

Git registra versiones de archivos. Repositorio es la carpeta acompañada por este historial; commit es un registro con cambios y mensaje. GitHub es un servicio que aloja repositorios remotos. Puedes usar Git localmente sin publicar nada en internet.

Por qué aprender

Cuando un agente altera muchos archivos, el historial permite entender qué cambió y recuperar una versión conocida. Git no sustituye la copia de seguridad de todo: archivos ignorados, bases de datos y datos externos necesitan protección propia.

Conceptos clave

Repositorio; commit; historial; remoto; backup.

En la práctica

Una gestora cambia el modelo de informe y pierde una sección. Un commit anterior preserva el contenido antiguo; un mensaje claro ayuda a localizar el cambio.

✓ Hazlo

Ejecuta git --version. En la carpeta de entrenamiento, usa git init -b main. No inicialices el historial en tu carpeta personal completa.

✗ Evita

Aceptar una conclusión sin comprobar la entrada que la sustenta.

2Observa antes de preparar

Qué es

git status muestra archivos nuevos, modificados y preparados. git diff muestra cambios aún no preparados; git diff --cached muestra lo que irá al próximo commit. El área de preparación, llamada staging, permite elegir exactamente qué archivos pertenecen al mismo cambio.

Por qué aprender

git add . prepara todo lo que no está ignorado. Para aprender, prefiere nombrar archivos: percibes mejor el alcance y reduces el riesgo de incluir material sin relación.

Conceptos clave

Árbol de trabajo; staging; diff; revisión de contenido.

En la práctica

Cambiaste README.md y creaste una anotación privada. git add README.md prepara solo la documentación. Antes del commit, git diff --cached confirma lo que se registrará.

Experimenta ahora

Ejecuta git status, git diff y git diff --cached. Si alguna salida está vacía, explica en qué etapa están los cambios.

3Guarda una versión con intención

Qué es

Configura user.name y user.email localmente para identificar la autoría. Prepara los archivos deseados y usa git commit -m con una descripción concreta. Un commit debe representar un cambio que puedas explicar y verificar.

Por qué aprender

Mensajes como “update” hacen que el historial sea poco útil. Una versión solo es un punto confiable si sabes si funcionaba y qué verificaciones se hicieron.

Conceptos clave

Autoría; mensaje; cambio cohesivo; verificación.

En la práctica

“Añade instrucciones para revisar ventas” indica lo que cambió. Después, git log --oneline muestra una lista compacta de los registros y sus identificadores.

Secuencia para experimentar

  1. Prepara una copia de entrenamiento.
  2. Configura git config user.name "Tu Nombre" y git config user.email "tu-email" en el entrenamiento. Prepara README.md y .gitignore y crea el primer commit.
  3. Registra el resultado observado y la próxima corrección.

4Clona y actualiza con cuidado

Qué es

git clone copia un repositorio remoto y su historial. git pull busca e integra cambios en la rama actual. Antes de actualizar, revisa git status. En un flujo inicial, git pull --ff-only acepta solo una actualización directa y se detiene cuando los historiales divergieron.

Por qué aprender

Actualizar una carpeta con cambios locales puede generar conflictos. El bloqueo del --ff-only es información útil: no lo eludas borrando trabajo. Inspecciona el historial o pide ayuda con el contexto.

Conceptos clave

Clone crea la carpeta; pull actualiza; branch es una línea de trabajo; divergencia pide revisión.

En la práctica

Clonaste un proyecto ayer y hoy hay nuevas instrucciones en GitHub. Sin cambios locales, --ff-only suele avanzar la versión. Con commits diferentes en ambos lados, detente e inspecciona.

✓ Hazlo

Clona el repositorio público de este curso en una carpeta separada. Lee antes de ejecutar cualquier programa recibido, inclusive de repositorios conocidos.

✗ Evita

Mezclar la copia de entrenamiento con archivos privados o trabajo en producción.

5Recupera sin borrar el historial

Qué es

git revert crea un nuevo commit que deshace un cambio anterior. Es adecuado para corregir un registro ya compartido. git restore descarta cambios no guardados de archivos elegidos; puede perder trabajo. No enseñes reset --hard como respuesta automática para cualquier dificultad.

Por qué aprender

Las herramientas de recuperación tienen consecuencias diferentes. Identifique si el cambio está solo en el archivo, en un commit local o publicado antes de elegir el comando.

Conceptos clave

Revert preserva el historial; restore descarta los cambios seleccionados; la recuperación exige diagnóstico.

En la práctica

En el entrenamiento, haz un segundo commit cambiando el título del README. git revert HEAD crea un tercer commit que restaura el título anterior, sin ocultar que el cambio ocurrió.

Experimenta ahora

Use git revert --no-edit HEAD solo después de confirmar que HEAD es el segundo commit de entrenamiento. Abra el README y verifique el resultado, no solo el mensaje de Git.

6Publique solo lo que revisó

Qué es

git push envía commits al remoto. Antes de eso, verifique la cuenta, la URL de destino, el alcance de los archivos y la ausencia de credenciales. Un repositorio público queda accesible a terceros; el privado también requiere control de acceso. Publicar un sitio es una etapa adicional, según el alojamiento.

Por qué aprender

Mezclar guardar y publicar lleva a una exposición accidental. Separe “registrar localmente”, “enviar a GitHub” y “poner el sitio en línea” en su lista de verificación.

Conceptos clave

origin; push; visibilidad; credenciales; publicación.

En la práctica

Un README local puede contener borradores. El commit preserva esos borradores en la máquina. Sólo envíe cuando haya decidido que pueden formar parte del remoto elegido.

Experimenta ahora

Use git remote -v y git status. Confirme la URL y revise el último commit con git show --stat antes de decidir el envío.

Su primer punto de recuperación

Use archivos ficticios y una carpeta de entrenamiento. Las prácticas con instalación, Telegram o VPS pueden requerir tiempo adicional para registro y configuración.

Git · solo en la carpeta de entrenamiento

Lea el bloque antes de usar. Campos como Su Nombre y usuario@ip-de-vps son ejemplos para adaptar; los comandos administrativos pertenecen solo a su entorno de entrenamiento.

git config user.name "Seu Nome"
git config user.email "seu-email"

git diff --cached

git log --oneline
