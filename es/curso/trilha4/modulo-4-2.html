1Una VPS es una máquina bajo su responsabilidad

Qué es

VPS es un servidor virtual alquilado: una computadora remota con memoria, disco y red. Usted administra usuarios, actualizaciones y procesos. Comience con una máquina pequeña compatible con la aplicación; no contrate GPU solo para llamar a un modelo por API. El modelo remoto se ejecuta en la infraestructura del proveedor.

Por qué aprender

Una máquina encendida no significa un servicio saludable. Los costos de VPS, almacenamiento y API son separados. Antes de contratar, defina lo que necesita ejecutar continuamente y quién verificará incidentes.

Conceptos clave

Servidor remoto; recursos; costo recurrente; responsabilidad operativa.

En la práctica

Un bot pequeño que consulta datos ficticios no necesita la misma infraestructura que un modelo local. La gestora estima carga, presupuesto y disponibilidad antes de elegir el plan.

✓ Hazlo

Complete materiais/plano-vps.md. Registre sistema operativo, forma de acceso, límite mensual, responsable y forma de apagar el recurso.

✗ Evita

Aceptar una conclusión sin comprobar la entrada que la sustenta.

2Entre por SSH y preserve acceso

Qué es

SSH crea una conexión protegida para administrar la máquina. Use la clave pública registrada según el proveedor y verifique la identidad del servidor. Cree un usuario de trabajo con permisos administrativos cuando sea necesario. Mantenga la sesión original abierta mientras prueba una segunda conexión.

Por qué aprender

Cambiar el firewall o la autenticación sin probar una ruta de recuperación puede bloquear su propio acceso. La consola del proveedor es la alternativa cuando la conexión normal falla; verifique que funcione antes de restringir la red.

Conceptos clave

Clave pública; huella digital; usuario; sudo; recuperación.

En la práctica

El comando ssh usuario@ip-de-la-vps abre la sesión. usuario e ip-de-la-vps son campos para sustituir, no valores reales. El nombre del prompt y pwd ayudan a confirmar en qué máquina estás.

Experimenta ahora

Prueba la segunda sesión antes de cerrar la primera. No desactives login ni cambies el puerto SSH siguiendo un comando sin saber cómo recuperar el acceso.

3Instale solo lo necesario

Qué es

Los ejemplos del laboratorio usan Ubuntu con apt. Actualice la lista de paquetes y revise la actualización propuesta. El bot base necesita Python 3; Git ayuda a transferir el proyecto. Node, Docker y Codex son opcionales según la aplicación, no una lista obligatoria para cualquier VPS.

Por qué aprender

Cada dependencia añade mantenimiento. Un servicio simple, con pocas piezas, es más fácil de explicar, actualizar y recuperar. Instalar herramientas por hábito crea trabajo sin aumentar la capacidad necesaria.

Conceptos clave

apt update; apt upgrade; dependencia; entorno virtual cuando sea necesario.

En la práctica

Secuencia de referencia: sudo apt update, sudo apt upgrade, sudo apt install git python3. El bot del kit usa solo la biblioteca estándar, sin instalar paquetes Python externos.

Secuencia para experimentar

  1. Prepara una copia de entrenamiento.
  2. Antes de confirmar la actualización, lee los paquetes involucrados. Verifica python3 --version y git --version, luego crea ~/projetos en la cuenta de trabajo.
  3. Registra el resultado observado y la próxima corrección.

4Proteja la red y las credenciales

Qué es

El firewall filtra conexiones de red. Para long polling, el bot necesita salir a HTTPS; no es necesario exponer un puerto del bot a internet. Antes de activar UFW, libere el puerto SSH realmente usado y verifique reglas locales y del proveedor. Restrinja el .env con chmod 600 y manténgalo fuera de Git.

Por qué aprender

Abrir todos los puertos para “hacer funcionar” amplía el riesgo sin diagnosticar la causa. Si el proceso no responde, la salida de red, el token y la ejecución merecen verificaciones distintas.

Conceptos clave

Entrada y salida; puerto SSH; regla de firewall; permisos de archivo.

En la práctica

Si SSH usa el puerto 22, sudo ufw allow 22/tcp puede ser apropiado. Si usa otro puerto, la regla necesita cambiar. Sólo ejecuta sudo ufw enable después de probar la configuración y el acceso de recuperación.

✓ Hazlo

Lista los puertos realmente necesarios en el plan. Registra qué comandos varían por proveedor y nunca trates el ejemplo de puerto como universal.

✗ Evita

Mezclar la copia de entrenamiento con archivos privados o trabajo en producción.

5Systemd supervisa el proceso

Qué es

systemd es el gestor de servicios de muchas distribuciones Linux. Una unidad describe qué programa iniciar, con qué usuario y en qué carpeta. Restart=on-failure reinicia tras una falla, pero no corrige un error persistente. El kit proporciona una unidad parametrizada para el usuario oswork.

Por qué aprender

Ejecutar el bot en una sesión SSH puede terminar el trabajo al cerrar la conexión. La supervisión permite reiniciar con la máquina y centralizar logs. No sustituye alertas, límites o análisis de la causa.

Conceptos clave

Unidad; usuario de servicio; directorio; reinicio; journal.

En la práctica

Después de adaptar las rutas, usa sudo systemctl daemon-reload y sudo systemctl enable --now oswork-bot. Consulta systemctl status y journalctl -u oswork-bot -n 50 --no-pager.

Experimenta ahora

Haz un reinicio controlado con systemctl restart, revisa /status y registra la hora. Si falla, detén el servicio antes de seguir repitiendo intentos sin diagnóstico.

6Disponibilidad exige rutina de cuidado

Qué es

La operación continua combina supervisión, actualización, monitoreo, copias de seguridad y restauración probada. Haga copias de los datos fuera de la máquina, proteja credenciales y defina retención. Una copia de seguridad solo se valida cuando restaura una copia y verifica el contenido.

Por qué aprender

Sin monitoreo, un servicio puede quedar detenido durante días. Sin prueba de restauración, la copia puede estar incompleta. La promesa real es una rutina recuperable, no una máquina infalible.

Conceptos clave

Chequeo externo; logs; copia de seguridad fuera de la VPS; restauración; límite de gasto.

En la práctica

Una verificación diaria registra la respuesta del bot y el espacio en disco. Una prueba mensual restaura vendas.csv en una carpeta separada y compara el total. Las credenciales siguen tratamiento privado, sin entrar en el backup público.

Experimenta ahora

Finaliza el proyecto con cinco evidencias: respuesta autorizada, bloqueo de desconocido, reinicio, log sin token y restauración confirmada. Declara cualquier paso no ejecutado.
