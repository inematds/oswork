MÓDULO 4.1

Telegram como interfaz de trabajo

Ejecute un bot restringido de consulta y entienda dónde entra la IA.

0% 0 de 0

Qué es

Un bot recibe mensajes a través de la API de Telegram y devuelve respuestas. La inteligencia puede provenir de reglas, de un programa o de una llamada a modelo. La aplicación en el celular no ejecuta sus tareas sola en el servidor: existe un programa intermedio con permisos definidos.

Por qué aprender

Separar interfaz y ejecución evita llamar a cualquier respuesta automática de agente inteligente. Primero construya un camino confiable para recibir y responder; luego conecte la capacidad necesaria.

Conceptos clave

Mensaje; Bot API; programa; agente; resultado.

Qué es

En Telegram, encuentre el BotFather oficial y use /newbot. Elija nombre e identificador según las instrucciones mostradas. El token generado autentica su programa ante Telegram. Guárdelo como TELEGRAM_BOT_TOKEN en un archivo privado; el kit solo tiene valores de ejemplo.

Por qué aprender

Quien controla el token puede operar el bot. Capturas de pantalla del proceso y URLs que contengan el token pueden filtrar acceso. Si hay exposición, revoque el token en BotFather antes de continuar.

Conceptos clave

BotFather; token; variable de entorno; rotación.

Qué es

El bot del kit solo acepta conversaciones privadas e IDs configurados. También solo acepta los comandos conocidos. Verificar el ID es diferente de verificar el nombre visible: los nombres pueden cambiar. Un mensaje de un desconocido no debe activar la lectura de archivos o comandos del sistema.

Por qué aprender

Un bot encontrado en internet puede recibir mensajes inesperados. La autenticación del programa con token no significa autorización de cualquier persona que le hable. Son controles distintos.

Conceptos clave

ID numérico; lista de acceso; conversación privada; comandos fijos.

Qué es

Long polling es el programa preguntar a Telegram por mensajes y esperar un poco cuando no hay novedades. Es simple para aprender y no exige abrir una puerta pública de entrada. Webhook es otra estrategia, en la que Telegram llama a una dirección HTTPS suya; no es necesaria en este laboratorio.

Por qué aprender

Elegir un único modo reduce problemas de configuración. Mantenga una única instancia buscando mensajes para un bot: procesos duplicados pueden disputar actualizaciones.

Conceptos clave

getUpdates; offset; timeout; instancia única; acceso de salida.

Qué es

El kit deliberadamente separa transporte y funciones de trabajo. Comienza determinístico: estado e informe de datos ficticios. Para acoplar IA, defina una función con entrada limitada, timeout, techo de salida y revisión. No exponga codex exec directamente a mensajes públicos ni desactive protecciones para hacerlo funcionar.

Por qué aprender

Un programa predecible permite probar la base sin gastar API. Después, evalúa si la IA mejora la interpretación, resumen o clasificación y mide el resultado con una referencia conocida.

Conceptos clave

Función de dominio; límites; timeout; revisión; datos mínimos.

Qué es

Pruebe remitente permitido, bloqueado, grupo, comando desconocido y datos ausentes. Los logs deben informar tipo de falla y hora, sin token ni mensajes privados completos. En el laboratorio, apagar el proceso debe detener las respuestas: eso prueba que el programa local está en el camino.

Por qué aprender

Una respuesta correcta no prueba que el bot esté restringido ni que recupere red. Un conjunto pequeño de escenarios demuestra las propiedades importantes antes de migrar a una VPS.

Conceptos clave

Autoprueba; falla de red; logs sin secreto; interrupción; diagnóstico.

MÓDULO 4.2

VPS desde cero y operación 24/7

Prepare un plan de despliegue, supervisión, respaldo y verificación del servicio.

0% 0 de 0

Qué es

VPS es un servidor virtual alquilado: una computadora remota con memoria, disco y red. Usted administra usuarios, actualizaciones y procesos. Comience con una máquina pequeña compatible con la aplicación; no contrate GPU solo para llamar a un modelo por API. El modelo remoto se ejecuta en la infraestructura del proveedor.

Por qué aprender

Una máquina encendida no significa un servicio saludable. Los costos de VPS, almacenamiento y API son separados. Antes de contratar, defina lo que necesita ejecutar continuamente y quién verificará incidentes.

Conceptos clave

Servidor remoto; recursos; costo recurrente; responsabilidad operativa.

Qué es

SSH crea una conexión protegida para administrar la máquina. Use la clave pública registrada según el proveedor y verifique la identidad del servidor. Cree un usuario de trabajo con permisos administrativos cuando sea necesario. Mantenga la sesión original abierta mientras prueba una segunda conexión.

Por qué aprender

Cambiar el firewall o la autenticación sin probar una ruta de recuperación puede bloquear su propio acceso. La consola del proveedor es la alternativa cuando la conexión normal falla; verifique que funcione antes de restringir la red.

Conceptos clave

Clave pública; huella digital; usuario; sudo; recuperación.

Qué es

Los ejemplos del laboratorio usan Ubuntu con apt. Actualice la lista de paquetes y revise la actualización propuesta. El bot base necesita Python 3; Git ayuda a transferir el proyecto. Node, Docker y Codex son opcionales según la aplicación, no una lista obligatoria para cualquier VPS.

Por qué aprender

Cada dependencia añade mantenimiento. Un servicio simple, con pocas piezas, es más fácil de explicar, actualizar y recuperar. Instalar herramientas por hábito crea trabajo sin aumentar la capacidad necesaria.

Conceptos clave

apt update; apt upgrade; dependencia; entorno virtual cuando sea necesario.

Qué es

El firewall filtra conexiones de red. Para long polling, el bot necesita salir a HTTPS; no es necesario exponer un puerto del bot a internet. Antes de activar UFW, libere el puerto SSH realmente usado y verifique reglas locales y del proveedor. Restrinja el .env con chmod 600 y manténgalo fuera de Git.

Por qué aprender

Abrir todos los puertos para “hacer funcionar” amplía el riesgo sin diagnosticar la causa. Si el proceso no responde, la salida de red, el token y la ejecución merecen verificaciones distintas.

Conceptos clave

Entrada y salida; puerto SSH; regla de firewall; permisos de archivo.

Qué es

systemd es el gestor de servicios de muchas distribuciones Linux. Una unidad describe qué programa iniciar, con qué usuario y en qué carpeta. Restart=on-failure reinicia tras una falla, pero no corrige un error persistente. El kit proporciona una unidad parametrizada para el usuario oswork.

Por qué aprender

Ejecutar el bot en una sesión SSH puede terminar el trabajo al cerrar la conexión. La supervisión permite reiniciar con la máquina y centralizar logs. No sustituye alertas, límites o análisis de la causa.

Conceptos clave

Unidad; usuario de servicio; directorio; reinicio; journal.

Qué es

La operación continua combina supervisión, actualización, monitoreo, copias de seguridad y restauración probada. Haga copias de los datos fuera de la máquina, proteja credenciales y defina retención. Una copia de seguridad solo se valida cuando restaura una copia y verifica el contenido.

Por qué aprender

Sin monitoreo, un servicio puede quedar detenido durante días. Sin prueba de restauración, la copia puede estar incompleta. La promesa real es una rutina recuperable, no una máquina infalible.

Conceptos clave

Chequeo externo; logs; copia de seguridad fuera de la VPS; restauración; límite de gasto.
